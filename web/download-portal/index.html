Attack-chain correlation

Recon, brute force and successful login from one source become a single critical incident, not three unrelated alerts.

From detection to response

Respond on your terms.

SOAR-Lite is intentionally small and auditable. Playbooks are plain YAML, scoped to critical incidents by default, and run at most once per incident. Start in dry-run, inspect the exact command, then enable it.

01

Match the incident

Severity, rule names, categories, correlation rules or alert count.

02

Preview the response

Dry-run renders every placeholder and records the intended command and recipients.

03

Act safely

Run argv-based commands without a shell, or reuse your existing SMTP settings for email.

Dry-run default No shell Fail-open One run / incident
Read the deployment notes
config/playbooks.yaml
dry-run 
enabled: true
dry_run: true
max_runs_per_incident: 1

playbooks:
  - id: "critical-block-source"
    match:
      severities: ["critical"]
    actions:
      - type: "command"
        command:
          - "iptables"
          - "-I"
          - "INPUT"
          - "-s"
          - "{src_ip}"
          - "-j"
          - "DROP"
        shell: false
Command failures never interrupt the detection pipeline.
